SECURITY NOTES (pre-coding, required by rules):
What someone with Drive write access but NO folder key could do to sync feature:
1. Create/modify sync files without proper encryption (unencrypted files visible to them)
2. Spoof device IDs by writing files with fake device signatures
3. Truncate or corrupt sync files, causing merge failures
4. Create sync files that fail authentication during merge

Defenses built in:
1. All sync files are encrypted with the folder key (DpxAuth wrapper), opened only after authentication
2. Device ID is the hex of the key ID (kid), authenticated in the Dpx envelope's header
3. Sync files must pass Dpx auth verification; failed auth is reported as UNREADABLE
4. The engine's merge logic verifies writer's kid against keys.json; unknown writers are skipped
5. No key.json error triggers revoke, re-key, wipe; only read-back is trusted
