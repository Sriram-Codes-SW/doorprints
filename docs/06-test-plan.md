### 14.1 The golden-file tests, and what they are actually for

TC-U-26 is the centre of this sprint's testing, because the risk it covers is peculiar: **the same format is
implemented twice**, once in Kotlin for Android and once in TypeScript for the web ([03](03-design.md) ADR-20).
Ordinary unit tests on each side would happily pass while the two drifted apart. So both sides build the **same
fixture** and compare the result against **the same checked-in expected files**:

| Side | Fixture | Golden files | Runner |
|---|---|---|---|
| Kotlin | `shared/src/commonTest/.../export/ExportFixture.kt` | `ExportGolden.kt` | `ExportGoldenTest` in `:shared:testAndroidHostTest` (also compiled for iOS, TC-U-37) |
| TypeScript | `web/src/app/export/golden/fixture.ts` | `golden/html.golden.ts`, `csv.golden.ts`, `markdown.golden.ts`, `backup.golden.ts` | `exporters.spec.ts` under Vitest in `web.yml` |

A change to a writer on one platform fails that platform's golden test; a change to the *format* fails both until
both are updated — which is exactly the review signal ADR-20 needs, and the reason the shared model takes the export
time and UTC offset as parameters rather than reading a clock.

The two also pin the arithmetic, not only the strings: `fixedFormatsWithoutAPlatformFormatter`,
`rupeesUseIndianGrouping` and the web's *"follows the Kotlin arithmetic where `toFixed` would disagree"* exist
because JavaScript's rounding and Kotlin's disagree on ties, and a copy whose prices differ by one rupee between
platforms would be a real defect.
